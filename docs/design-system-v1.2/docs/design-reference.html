Design system v1.2 · color and type · 29 October 2026

Black, gray and white. Peach in six places. Red only for delete.

Every swatch, button and screen on this page is drawn with the real tokens, so what you see is exactly what Codex should build. The full written spec, with the token file, is docs/design-system.md.

Background 54%Surface 16%Raised 10%White text and state 16%Peach 2–3%Red, only when deleting
Roughly how any Loupe screen should read, not counting the user's images.

The whole palette

14 values cover the entire product. v1.1 had 8 grays and 7 text levels, and that spread is where the mismatched buttons came from. Hover is no longer its own gray: it's a thin white veil over whatever is underneath.

Three surfaces, nested

Each step sits inside the one before it. Nothing in the UI uses a fourth gray.

No green, blue or yellow anywhere in the interface. Success is white text and a check. Image palettes, color-chip swatches and board covers are the user's content, so they keep whatever colors the images have.

Peach: six places, nothing else

One peach, always flat. No darker shade, no browner shade, no gradient, no tint. If something looks peach-brown in the build, it's an old value or a gradient, and it's a bug.

Hand this to Codex

The rules and tokens live in docs/design-system.md. The pass prompts in the prompts folder tell Instinct what to change and test, one surface at a time. The block below is the short version.

Prompt

DESIGN SYSTEM v1.2 is the source of truth for every color, size and weight.
If code, v1.1 or any older doc disagrees, v1.2 wins. docs/design-reference.html
shows every element drawn with the real values; docs/design-system.md has
the token CSS and the full element map.

1. Replace src/styles/tokens.css with the complete token block in
   docs/design-system.md.
2. Replace every hardcoded color, radius and font size in src (and the Chrome
   extension, iOS share extension, Figma and Canva plugins) with a token.
3. Apply the element map component by component. Anything not listed: copy
   the closest listed element, else white or gray. Never peach.
4. Fix every numbered issue in "Your two screens: now vs fixed".

Hard rules
- App icon and favicon: peach square, #0E0E0E circle in the middle (40%
  of width). Use the files in docs/assets/. Never redraw them.
- Peach #EF8A66 only in: logo dots, avatar, phone FAB, extension Save,
  annotation strokes, marketing CTAs. Always flat in the product.
- Primary buttons are white with #0e0e0e text. Five button kinds only:
  Primary, Secondary, Ghost, Danger, Brand.
- Active, selected, checked and focused states are white.
- Three surfaces only: #0e0e0e, #141414, #1c1c1c. Hover is a 6% white veil.
- DM Sans only. Sizes 26/22/20/17/15/14/13/12/11. Weights 400/500/600.
- Sentence case, no uppercase labels, nothing under 11px.
- Corners 6 / 10 / 16 / pill. No square corners anywhere.
- Every :hover inside @media (hover:hover) and (pointer:fine).

Autonomous mandate: inspect existing source before changing anything, don't
guess, decide at ambiguous points and note the decision, run the build, and
pass the checklist before reporting complete.
